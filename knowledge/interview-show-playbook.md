# Interview Show Playbook — 線上訪談節目生產線

> **節目定位：螢幕優先的拆解型訪談** —— 主畫面是來賓的作品與後台真數據，不是兩顆頭在講話。
> 這份是「為什麼這樣做」；「你的節目怎麼做」填 `templates/interview/format_bible.template.md`，
> 節目識別（節目名／主持人／片尾招牌句／平台清單）填 `profiles/show.md`。
>
> 機械層：`src/interview_gate.py`（來賓資料閘門）＋ `src/interview_autopilot.py`（一鍵流程）
> ＋ `src/longform_maker/plan_gate.py`（包裝先行閘門）。**規則能機械化的都機械化 —— 不靠記憶，靠 gate 擋。**

---

## §0 三十秒版

| 問題 | 答案 |
|---|---|
| 為什麼做訪談？ | **成就框架的供給量**。自己的成就有限，來賓池是無限的；而且來賓自帶外部點火 |
| 主畫面放什麼？ | 來賓的作品／後台真數據／現場 demo。**兩顆頭是配菜不是主菜** |
| 挑人標準？ | **有可截圖驗證的具體成果** —— 沒有真數據的來賓不上（gate 直接擋） |
| 多長？ | 12-15 分鐘起手；素材夠硬才拉長，撐不住砍到 8-10 分 |
| 怎麼錄？ | **分軌本機錄**（不錄雲端混音軌）＋雙備援 |
| 剪什麼？ | **砍漫談，不砍停頓** —— 整段沒資訊量就剪整段，不要把人剪成機關槍 |
| 標題怎麼下？ | **來賓的成就框架**（「他用 X 做到 Y」），不是「專訪 XXX」 |
| 誰蓋合規章？ | **人**。程式只會寫「待複核」，簽章要人跑過 checklist 才給（見 §8） |

## §1 為什麼是訪談（戰略理由）

成就框架（「某人做到了 X」）通常強於工具框架（「這個工具怎麼用」）—— 因為它有**實錘**：
畫面上有一個可驗證的結果。問題是**你自己的成就是有限的**，一年做不出幾個新戰績。

訪談解決的就是這件事：

1. **成就框架供給量**：來賓池 = 無限的成就框架來源，而且每一個都是新故事。
2. **外部點火內建**：發布日來賓分享給自己的受眾 = 免費的外部流量，而且是精準受眾。
3. **同一條線換格式，不是換線**：訪「用你的題材做出成績的人」＝ cluster 不變、格式變。
   （`profiles/show.md` 的 `CLUSTER` 就是這個用途，`plan_gate` P5 會檢查。）

⚠️ 訪談線建議放在實驗配額裡（例如 80/20 的那個 20%）。**判生死看 3 集平均，不看單集**；
前 3 集不因單集數據差轉向 —— 新格式的前幾集在教演算法「這是什麼」。

## §2 一鍵流程（三段，中間只有三次複製貼上）

```
1) invite   python src/interview_autopilot.py invite 01 --name "小明" --hint "用 X 做到 Y"
            → 邀約包（三種關係溫度的訊息）＋ 來賓資訊表 ＋ _guest.py 骨架
            ↳ 你：挑一則貼給對方

2) plan     把對方回填的資訊填進 _guest.py（AI 助手可代填）
            python src/interview_autopilot.py plan 01 --compliance-ok
            → 過兩道閘門 → 產 7 件套 → 排程進 channel_tracker
            ↳ 你：把「準備包＋授權書」貼給對方

3) build    錄製當天開著 host_script.md 照唸；錄完丟素材
            python src/interview_autopilot.py build 01
            ↳ 你：發布日把「來賓分享文」貼給對方
```

**主持台本是整條線的傻瓜化核心**：開場逐字稿、每段轉場句、⏱ 時間提示、
⚡ 追問句庫（「所以具體是怎麼做的？」＝來賓講空話時的萬用武器）、收尾三題、片尾招牌句 ——
錄製時照著第二螢幕唸就好。**不露臉的節目可以看稿，這是格式給你的優勢。**

## §3 七件套（`plan` 一次產完）

| 檔案 | 給誰 | 重點 |
|---|---|---|
| `EP{N}_host_script.md` | 主持人 | **只寫主持人的部分**：cold open 逐字稿／串場句／⚡ 追問庫／「三個可帶走」收斂模板／片尾 |
| `EP{N}_outline_for_guest.md` | 來賓 | 依 beat 結構的問題方向。**自動拿掉 ⚡ 追問陷阱題** |
| `EP{N}_guest_prep_kit.md` | 來賓 | 錄音三件事／要準備的截圖清單／流程說明 |
| `EP{N}_consent_form.md` | 來賓 | 授權書（可上鏡數據項逐條列出）。**簽了才錄** |
| `EP{N}_recording_checklist.md` | 主持人 | 錄製日照表操課（錄前一天／錄前 10 分／錄製中／錄後當場） |
| `EP{N}_publish_kit.md` | 主持人 | 8 組包裝候選＋主打標題／縮圖概念／說明欄／點火文／**來賓分享文** |
| `EP{N}_shorts_cuts.md` | 主持人 | 2-3 個預標切條點（錄完依實際內容修訂） |

**來賓永遠不給逐字稿** —— 照稿唸＝災難。來賓拿到的是方向，主持人拿到的才是逐字稿。

## §4 六條鐵則（違反＝重做）

1. **來賓數據上鏡＝真截圖**：要嘛來賓提供真後台截圖（授權書載明），要嘛不上鏡。
   **禁自繪重建來賓戰績** —— 引用別人的數字時自繪最糟：既無法自證，又替對方擔了造假風險
   （見 [`meta-lessons.md`](meta-lessons.md) M107）。
2. **拆解型不聊天型**：每段必須產出可操作內容。主持人的職責是**打斷漫談＋追問「所以具體怎麼做」**。
3. **來賓不給逐字稿**；主持人的 cold open／串場／總結才是逐字稿（過 `script_gate.py`）。
4. **授權書簽了才錄；初剪來賓看過才發布**。爭議段落來賓有否決權，這兩步沒有例外。
5. **分軌本機錄**（不靠雲端混音軌）；來賓手機錄音備份必開。
6. **判生死看 3 集平均**，不看單集；前 3 集不因數據差轉向。

## §5 Beat 結構（12-15 分鐘版）

| 時間 | Beat | 內容 | 誰主導 |
|---|---|---|---|
| 0:00-0:30 | cold open | 來賓戰績數字＋一句懸念（**前 30 秒為陌生人設計**，禁內部梗） | 主持人 |
| 0:30-1:30 | 成就證據 | 來賓真後台截圖上鏡，引導「這數字怎麼來的」 | 來賓 |
| 1:30-4:30 | 拆解一：起點 | 怎麼開始的＋**當時卡在哪**（挫折點必問，別只講順風） | 來賓 |
| 4:30-8:30 | 拆解二：核心方法 | 來賓螢幕分享現場 demo（**本集最大資訊塊**） | 來賓 |
| 8:30-11:00 | 拆解三：踩雷 | 「如果重來，哪一步不會再做」（觀眾最愛聽，不要草草帶過） | 來賓 |
| 11:00-12:30 | 三個可帶走 | **主持人收斂總結**，不是來賓漫談 | 主持人 |
| 12:30- | CTA＋片尾 | 來賓連結＋社群＋訂閱 | 主持人 |

節奏規則：每 5-8 分鐘一個明確段落；**任何一段 >90 秒沒有可操作內容＝剪掉**。

錄製時的兩個小動作，剪輯會省你一小時：
- 請來賓**親口講一次核心數字**（cold open 要用）。
- 每段結束口頭標記「好，下一段」（剪輯找點用）。

## §6 線上錄製規格

- **分軌本機錄**：用能讓雙方各自本機錄原檔、事後上傳的工具。
  備援鏈：主工具 → 視訊會議（開原音＋本機錄）→ 最後才雲端混音軌。
- **鐵三角**（寫進來賓準備包）：耳機必戴／有線網路或坐路由器旁／光源在臉前。
- **雙備援**：來賓手機錄音全程開；主持端本機同錄。**兩邊都可能壞，只有一份就是賭運氣。**
- 目標規格：音 48kHz 分軌 WAV；來賓螢幕分享請對方**同時本機錄 1080p**（雲端壓縮的介面字會糊）。
- 錄前 5 分鐘：試音 30 秒**回放**確認、雙方關通知、來賓關無關分頁。
- 錄後當場：**確認雙方本機檔已到手才下線**（人下線了檔案就難追）。

## §7 剪輯規則

- **砍的是漫談不是停頓**：整段沒資訊量 → 剪整段；不要把每個呼吸都剪掉，人會變機關槍。
- **來賓螢幕錄影＝預設有毒**：先過 `src/longform_maker/screen_clean.py` ＋全幀掃描
  （來賓的通知／私訊／分頁／後台）。**比自己的素材更嚴** —— 洩漏的是別人的隱私
  （見 [`meta-lessons.md`](meta-lessons.md) M91）。
- 分軌各自過音訊鏈（壓縮＋loudnorm）再混，不要混完才處理。
- **講者字幕**：來賓句首加標記（例「G：」）或講者色塊，**二選一後全系列固定**。
- demo 段三速：講解 1x／純操作 2-4x／等待畫面 cut 掉。
- b-roll：來賓的作品畫面優先；廢話段蓋 b-roll **保留音軌**。
- BGM：訪談人聲密度高，比獨白片再壓低、duck 更深。
- 交付：`delivery_qa` 全綠＋逐幀掃描＋**來賓審看初剪**。

## §8 包裝與演算法定位

- **標題＝來賓的成就框架**：「他用 X 方法兩個月做到 Y」。
  **不要用「專訪 XXX」** —— 人名對陌生人是零資訊，除非來賓自帶流量。標題賣的是他做到的事。
- **縮圖**：來賓真數據截圖當主體（紅圈放大、其餘壓暗）＋起點狀態白字。
  來賓的臉需**本人同意**才放；自己出不出鏡照 `profiles/brand.md`。
- **機器歸屬：推薦機**。訪談沒有搜尋量，靠 CTR/AVD 起飛；外部點火由來賓分享提供。
- **包裝先行**：`plan` 會產 8 組「標題 | 縮圖」候選丟給 `plan_gate`。**包不出 8 組就砍題** ——
  8 組是門檻不是目標。

### 🔑 合規章只能由人蓋（這是刻意的設計）

`plan` 預設在規劃文件寫「**合規：待複核**」→ 被 `plan_gate` P4 **擋下**；
跑過平台 AI 內容政策 checklist 之後，人工加 `--compliance-ok` 才會改寫成「合規：通過」。

**為什麼不讓程式自動蓋章**：如果產生規劃文件的程式可以自己寫「合規：通過」，
那道合規閘門就是**機器自己滿足自己**＝永遠是綠的＝等於不存在（假綠）。
閘門的價值來自「有一件事機器做不到、非人不可」。訪談片牽涉**他人的肖像與聲音**，
出事的是來賓不是你，這一章尤其不能自動蓋。

同樣的道理適用於任何「宣告式」的 gate（合規、審看、授權）：
**能被受檢者自己蓋的章，不是章。** 讓機器擋住流程、把簽名留給人。

## §9 來賓池策略

優先序（範例，照你的生態調整）：

1. **自己社群內有真實戰績的成員** —— 熟人容錯高、故事貼頻道敘事、社群飛輪。
2. **用你的工具／方法做出成績的人** —— 雙重敘事（工具 + 人）。
3. **同題材的其他創作者** —— 帶自己的受眾來。

**挑人唯一標準：有可截圖驗證的具體成果。** 沒有真數據的來賓不上 ——
這是節目底線不是裝飾，`interview_gate.py` 的 I-B 就是這條的機械版（沒有 achievements 直接擋）。

邀約三種關係溫度（熟人／半熟／陌生）的訊息在 `templates/interview/invite_pack.template.md`，
陌生版一定要寫清楚四件事：**時長、是否需出鏡、審看權、有無金錢往來**。

## §10 檔案地圖

```
src/interview_autopilot.py              一鍵流程（invite / plan / build）
src/interview_gate.py                   來賓資料閘門（I-A~I-E）
src/longform_maker/plan_gate.py         包裝先行閘門（P1-P5，含 P4 合規）
src/channel_tracker.py                  排程（pre-call / 錄製日 / 發布日 + D2/D7/D28）
templates/show_profile.template.md      → profiles/show.md（節目識別）
templates/interview/*.template.md       所有交付檔的文案 SoT（`((欄位))` 佔位）
templates/interview/format_bible.template.md  你自己的節目格式 bible（填空）
```

**骨架在 code、文案在 templates**：要改話術／條文／標題公式，改 `templates/interview/`，
不要改程式。程式只做欄位替換，而且**未填的欄位會直接 raise** —— 不會交出帶 `(( ))` 的檔案。
