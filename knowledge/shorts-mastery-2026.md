# Shorts Mastery 2026 — 直式短片結構層知識（fill-in-your-own-data）

> **這是「結構層」**：片長／首刀／loop／常駐識別／字幕資訊密度／判生死看哪個指標。
> 字幕樣式、hook 公式、安全區那些**呈現層**規則在 [`shorts-reels-best-practices.md`](shorts-reels-best-practices.md)，兩份互補不重疊。
>
> 本檔＝知識層；**機械層＝你自己的 shorts gate（每條規則對應一個 assert）＋一鍵 pipeline**。
> 規則能機械化的都該機械化 —— **剪 Shorts 不靠記憶，靠 gate 擋**。
>
> ⚠️ §1 的門檻數字**必須用你自己的頻道數據填**。這裡給的是方法與相對關係，不是可以照抄的常數
> （同一組門檻在不同題材／不同語言市場／不同頻道成熟度上會整組平移）。

## §0 三十秒版（趕時間只看這段）

| 問題 | 答案 |
|---|---|
| 片長多長？ | **13-25 秒**（梗／單一驚奇）或 **45-60 秒**（教學／demo）。**26-44 秒是死區 —— 但這是 YouTube Shorts 的校準，別的平台不成立**（見 S8） |
| 開場放什麼？ | **主體名大字 + 一句這是什麼**（2 秒內），不是直接跳內容 |
| 第一刀何時？ | **≤2.0 秒**（2 秒法則） |
| 字幕寫什麼？ | **讀畫面上的字**（品名+價格／招牌／介面文字），不是形容詞 |
| 怎麼結尾？ | 末段回到首段同一鏡頭且**末幀==首幀**（真 loop），接點不掛字幕 |
| 識別資訊放哪？ | **全片常駐**底部小字（不是只放片尾） |
| 判斷生死看什麼？ | **續看率**（三級門檻用你自己 3-5 支片校準，見 §1） |

## §1 Shorts 的指標系統（用你自己的數據填）

長片有雙機器（推薦機／搜尋機），**Shorts 同構**：同一支片可能被推薦機接走、被搜尋機接住、或兩邊都不要（雙殺）。
差別在**入口指標不一樣** —— Shorts 沒有縮圖可以點，所以整套 CTR 邏輯要換算。

### 1-1 CTR 的等價物 ＝ 第一幀 ＋ 前 1 秒

Shorts 是**自動播放**的：觀眾不是「看到縮圖決定要不要點」，而是**片子已經在播了，用大拇指投票要不要留下**。
所以長片的「CTR 工程」在 Shorts 上全部壓縮進 **第一幀構圖 + 前 1 秒發生什麼事**。

- **鐵則：不要用氣氛遠景開場**。遠景沒有視覺焦點 → 大拇指在你「鋪陳」完之前就滑掉了。
- 改用：**高對比主體近景**（食物／動物／物件／人臉），或**有消失點的引導線構圖**（把眼睛強制帶到畫面中心）。
- 驗證方式：把首幀**單獨輸出成一張圖**來看（不要憑剪輯時的印象）。一張圖看不出「這是什麼、為什麼有趣」＝這支開場沒過。

### 1-2 AVP 的等價物 ＝ 續看率（分發閘門）

**續看率（看完/滑掉的比例）＝ Shorts 版的分發閘門**：過了門檻推薦機才會放大，沒過就只剩搜尋機能救。

**三級門檻請用你自己的片校準**（下面是校準方法，不是抄現成數字）：

1. 取自己**最近 3-5 支** Shorts，全部讀同一個天齡窗（例如 D7）的續看率。
2. 排序後標出三個帶：
   - **上帶（推薦放大）** ＝ `<fill in>%` 以上 → 這支被推薦機接走，量會明顯高出其他片一個級距。
   - **中帶（推薦不放大、搜尋接住）** ＝ 約 `<fill in>%` → 推薦機沒放大，但**題目含搜尋需求詞**時，搜尋流量會持續補量（看流量來源佔比確認）。
   - **下帶（判死）** ＝ `<fill in>%` 以下 → 推薦當場判死；題目又沒有搜尋量 ＝ **雙殺**（無推薦、無長尾）。
3. 每累積 3 支新片就重算一次（門檻會隨頻道畫像漂移）。

⚠️ n=3~5 的門檻只能當 **checklist**，不能當定律押 —— 標成 PLAUSIBLE，別拿去做重大決策的唯一依據
（分級體例見 [`viral-playbook-framework.md`](viral-playbook-framework.md) §3）。

**流量來源要一起讀**：續看率中帶但流量結構是「搜尋佔多數」＝ 題目有需求、包裝沒過推薦關；
續看率下帶且**未訂閱觀看佔比很低**（大部分是自己人在看）＝ 這支根本沒發出去，改包裝也救不回，直接進下一支。

### 1-3 續看率 vs 循環率是**兩個獨立指標**

- **續看率**量「**留下多少人**」→ 決定分發。
- **循環率**（>100% ＝ 有人重看）量「**留下的人多熱情**」→ 是推薦放大的**強訊號**，但它救不了續看率低的片。
- 兩者可以背離：續看率高但循環率平（看完就走，正常）、續看率低但循環率高（小眾但死忠 → 題材對、包裝錯）。
- **不要把兩個混成一個「觀看表現」**看 —— 混起來就沒有可行動的結論。

### 1-4 定位：Shorts 是**拉新機器**不是變現機器

- **RPM 與長片差一個量級**（不是差幾成，是差一個級距）。填你自己 Studio 的數字對照：
  Shorts RPM `<fill in>` vs 長片 RPM `<fill in>` → 換算成「一支 Shorts 要多少 views 才等於一支長片的收益」，
  你就會停止用 Shorts 追收益。
- Shorts 的產出是**新觀眾**（未訂閱觀看佔比通常極高，填你自己的：`<fill in>%`），不是收益。
- **搜尋型 Shorts 幾乎不轉訂**（一次性需求：查完就走）；**推薦型 Shorts 才有轉訂**。
  所以「這支要拉訂閱還是要吃搜尋」在**選題階段**就決定了，不是剪完才想。
- 轉訂讀數請用**同天齡窗**跨片比較（D7 對 D7），且用「每萬觀看轉訂數」而不是絕對值。

## §2 外部研究基準（S1-S12，2026；第三方共識非官方）

> ⚠️ **出處狀態：二手・無連結。** 這 12 條是 2026 年做 Shorts 研究時從多家第三方工具商／創作者社群
> 彙整下來的共識值，**本 repo 沒有為其中任何一個數字保留可點的原始出處**，也沒有一條來自平台官方文件。
> 所以它們的正確用法是**假設**：拿來決定「該量什麼、往哪個方向調」，不是拿來判死自己的片，更不要在你自己的
> 內容裡把它們當成事實引用（引用要連結，沒連結就別給數字）。**S1-S12 全部應該用你自己的 Shorts 重新校準**
> ——真正會擋你 build 的門檻在 [`shorts_gate.py`](../src/longform_maker/shorts_gate.py) 的 `DEFAULT_RULES`，
> 那裡的每個值都可以用 `rules={...}` 覆寫。

| 編號 | 規則 |
|---|---|
| S1 | 種子池 50-500 人（2026 約 70% 非訂閱者），30-60 分鐘第一道門；**上架後 60 分鐘內禁改標題/封面/描述** |
| S2 | 擴散門檻依片長分班：<30s 要 AVD ≥55%／30-60s ≥45%，且 3 秒滑掉率 <25% |
| S3 | 2026 主訊號＝**watch-time-per-impression**；6 秒觀看放 15s 是正分、放 60s 是強負分 → **片長只開到撐得住的長度** |
| S4 | 訊號權重：前 3 秒留存 > 完播 > 重看 > 分享 > 留言 > 讚；DM 分享 > 其他分享；長留言 > 短留言 |
| S5 | **2 秒法則**：2 秒內給到 hook 多留 19% 觀眾；撐過 2 秒完播機率 +60% |
| S6 | 滑掉率分級：<15% 頂標／15-25% 健康／25-35% hook 有問題／>35% hook 失敗。**>25% 一律判「開頭問題」，不准去動中段** |
| S7 | 健康曲線：3 秒 >80%、中點 >60%、平均觀看百分比 >70%，前 5 秒應該是平的 |
| S8 | **片長雙峰**：梗/單一驚奇 13-25s；教學/demo 45-60s；**26-44s 是死區**。⚠️ **僅限 YouTube Shorts** —— 逐幀量測一批 IG/FB 直式短片，其中 31.8s 與 30.1s 兩支正好落在該區間、表現正常（其中一支還是那批互動最高的）。`shorts_gate` 因此改成**平台感知**（`spec["platform"]` ＝ `yt_shorts` / `ig_reels` / `fb_reels`），**跨平台硬擋＝假 BLOCK**。量測方法與樣本 → [`vertical-teardown-method.md`](vertical-teardown-method.md) §8 |
| S9 | Loop 要「第二次有新資訊」：末幀構圖=首幀（觸發重看），但關鍵彩蛋放最後 1 秒；純無縫騙自動重播只灌總 view 不灌 engaged view |
| S10 | Shorts→長片：轉訂率 `<fill in>`（**後台讀數，本表不給值** —— 依 §1-4 用「每萬觀看轉訂數」在同天齡窗跨片比較，D7 對 D7）；**三處都掛**（related-video link + 描述首行 URL + 置頂留言） |
| S11 | **稀釋風險在受眾組成不在演算法**：Shorts 與長片是兩套推薦系統，發爛 Shorts 不扣長片分；真正的傷害是題材出簇帶進不看長片的訂閱者 → 次要題材的 Shorts 應視為**獨立軌道，不計主線 KPI** |
| S12 | Shorts **28-30 天 EOL**：舊片推薦量斷崖 → KPI 只看 28 天；長片的 Shorts 導流窗實質一個月，**長片上架 72h 內把 2-3 支 Shorts 出完** |

## §3 剪輯鐵則（S-A ~ S-L ＋ S-O 機械標籤 ＋ S-M / S-N 人工項）

> 每條都是實剪被抓錯後定版的 → 對應 assert 見
> [`meta-lessons.md` §Shorts 結構教訓](meta-lessons.md)。這裡寫「怎麼做」，那裡寫「症狀/根因」。
>
> ⚠️ **標籤權威來源＝[`src/longform_maker/shorts_gate.py`](../src/longform_maker/shorts_gate.py)**：
> **S-A~S-L 是該檔定義的機械規則標籤，與程式的失敗訊息一一對應**
> （gate 報 `S-B 片長 31.0s 落在 26-44s 死區`，你在本檔查 S-B 就該查到片長帶）。
> 其中 S-A~S-I 有 assert 會直接擋 build；S-J~S-L 是該檔標為【內容】層的三條，靠人看畫面；
> **S-O 在程式裡是 warn 級**（會量、會報數字，但不擋出片）。
> **S-M / S-N 是本知識檔獨有的人工判斷項，程式裡沒有這兩個標籤、沒有 assert**，
> 純靠交付前人眼複核。改標籤時以程式為準，別反過來。
>
> ⚠️ **新規則一律往後接新字母，不要重用** —— 兩份文件各自編號就會撞號，
> 使用者照著 gate 訊息查文件會查到完全不相干的規則（v0.10.0 修過一次 S-B / S-H 撞號）。
> 這也是為什麼字母跳過 S-M / S-N 直接到 S-O：那兩個已經被本檔的人工項佔走了。

### S-A 這是「介紹一個主體」不是「素材剪輯」🔴
**開場 2 秒 = 主體名大字 ＋ 一句這是什麼**。觀眾第一秒就要知道在看哪一家/哪個地方/哪個東西，以及它是什麼。
- 正確示範：`「<地名> <店名>」＋「<一句話定義：例如 木頭櫃檯的甜點店>」`／`「<地名> <景點名>」＋「<一句話定義：例如 山谷裡的步道>」`
- 錯誤示範：主體名縮在底部小字、開場直接跳商品 → 看完不知道自己看了哪裡
- 根因：把任務理解成「把素材接起來加字幕」。**開剪前先寫一句「這支片要讓觀眾記住什麼」**，答不出「哪個主體＋它是什麼」就不准動手
- gate：驗首段內有 place + what 兩條，首條必須含 place

### S-E 識別資訊常駐，不是片尾一張卡 🔴
底部半透明小字條（地址／帳號／店名）**從 0.2s 掛到片尾**。Shorts 觀眾任何一秒滑進來都要知道「這是哪」；
資訊壓在最後＝前十幾秒的觀眾等於沒收到。
- 位置：壓到字幕帶底部，與逐句內容字幕**錯開 y 值**（否則會被蓋掉，見 `meta-lessons.md` M13）
- gate：缺常駐條直接 build 失敗

### S-J 字幕要「讀」畫面上的字，不是「看」外觀寫形容詞 🔴
畫面裡有標價牌／菜單／招牌／介面文字 → 字幕必須是上面的**品名＋價格**（或介面上的真實字串）。
- 錯誤示範（句型，不是真字幕）：「{顏色}的那個」「{形狀}那顆」「{質地}厚厚一層」＝零資訊形容詞
- 正確示範：`「<品名> $<價格>」`（照牌抄）
- 做法：疑似有文字的畫面 `crop+scale` 抽高解析度幀放大讀（掃描階段自動產「招牌放大圖」資料夾）；**讀不到就不編**
- **S-L 品名只能取「該主體正上方那張牌」** —— 不是同畫面別盤的牌，更不是別段讀到的牌（把 A 的價格套到 B 上是實際犯過的錯）
- **S-K 運鏡片段須逐 0.5s 驗證鏡頭全程沒移開該主體**（實例：某段 12.7s 後鏡頭已搖到別的東西上，字幕還掛著）

### S-F 字幕綁 segment 索引，禁手算時間軸 🔴🔴
**症狀**：整組七條字幕晚一段、兩句對調、末句掉進 loop 段。舊 gate 只驗 S-H「不跨 cut」——
每條都落在某一段內，只是**落錯段**，於是全數放行。
**永久解**：`caps_by_seg=[(segment_index, blocks, kind)]`，時間由 `expand_caps()` 之類的展開函數自動算
（同段多條自動平分）。**人不碰時間軸 → 配錯段在結構上不可能發生**。
- 配套：S-G loop 段禁掛內容字幕；交付前逐條字幕抽中點幀人眼複核（build 階段自動產字幕對照圖）

### 其餘既有規則（機械層 · 標籤同程式）
- **S-B 片長雙峰帶，避開 26-44s 死區**：片長只收梗/單一驚奇帶（範例校準 13-25s）或教學/demo 帶（45-60s），
  **26-44s 是死區**（S8；兩頭不沾）。門檻在 `DEFAULT_RULES` 的 `dur_min` / `dur_max` / `dur_deadzone`，**請用自己的片重新校準**
  - **平台感知**：帶寬與死區的預設值由 `PLATFORM_RULES[spec["platform"]]` 提供
    （`yt_shorts` 有死區；`ig_reels` / `fb_reels` 沒有、13-60s）。不寫 `platform` ＝ `yt_shorts`（舊行為）。
    平台只給**預設值**，`rules={...}` 仍逐項覆寫且優先；**平台名打錯直接擋，不靜默 fallback**
- **S-C 首刀 ≤2.0s**（S5 2 秒法則的可執行版）
- **S-D loop 對齊**：末段須回首段同 clip，且**末段結束點 == 首段起始點**（運鏡片光是「回同一支 clip」不夠，相機已經移開了）
- **S-H 字幕不跨 cut**：一條字幕只能活在一個 segment 之內，不准橫跨剪接點。
  由 S-F 的 `expand_caps()` 在段界內算時間（含 `cap_pad` 留邊）**結構性保證** —— 人不碰時間軸，就跨不出去
- **S-I white-first**：字幕底一律白，每支僅 ≤2 個非白色（重點=金、資訊=淺）
- **S-O 換句節奏（warn 級，不擋出片）**：內容字幕中位停留 ≤1.8s、換句 ≥30 句/分。
  依據＝逐幀量測一批市面直式短片的 39.7-75.4 句/分，而且**每一支的換句速率都高於剪點速率**
  → **直式的節奏主體是換句不是剪點**；素材不夠就讓字幕推進，別硬切
  （方法與數據 → [`vertical-teardown-method.md`](vertical-teardown-method.md) §2-§3）。
  門檻在 `cap_dwell_warn` / `cap_rate_warn`，gate 回傳 `cap_rate` / `cap_dwell` 兩個量測值。
  ⚠️ **只 warn 不 fail**：樣本全是成功片、**沒有失敗對照組**，只能說「成功的都這樣」。
  不確定的知識就報數字給人看，不要替人判死 —— 一個天天吵的規則等於沒有規則

### 人工判斷項（S-M / S-N · 程式沒有這兩個標籤，沒有 assert）
- **S-M 最強一幀放最前**（Shorts 沒有留壓軸的餘裕）——「壓軸」在這裡等於沒人看到。
  複核方式：首幀單獨輸出成圖，自問「只看這一格，我會停下來嗎」
- **S-N 首幀用近景高對比主體**（食物/動物/物件，或有消失點的引導線構圖），不用氣氛遠景（§1-1）。
  同樣不憑印象：**首幀出圖來看**

### 技術基礎（首批落地時踩出來的）

1. **旋轉正規化**（手機 .MOV 一定要做，混向素材也吃）：
   `ffmpeg -i clip -vf "scale=1080:1920:force_original_aspect_ratio=increase,crop=1080:1920,fps=30,setsar=1" -an`
   ffmpeg 預設 autorotate 會套 rotation 旗標 → 全部轉成 upright 9:16。
2. **GPS → 地址**：`ffprobe -show_entries format_tags=com.apple.quicktime.location.ISO6709` 抽 GPS
   → 反查地名＋地址（S-E 要用）。海拔還能驗「山上景點 vs 平地」。
3. **emoji 一律移除**：libass + 一般 CJK 字型沒有 emoji glyph → 出豆腐框。真要 emoji 改走 PNG sticker overlay。
4. **BGM**：無人聲時當主音，抓高光起播（能量最大的窗，見 `meta-lessons.md` M98）＋ `acompressor` 壓平（M99），
   loop + fade，音量 0.40-0.45，成片 LUFS -14。
5. **字幕 ↔ clip 抽幀驗**（M9/M87）：每個 clip 對應一個主體，配錯就糗。
6. **helper 化**：把「片段→多色字幕→配樂」封成一個 `build_one_short()` 級的函數，
   再包一層一鍵 CLI；不要每支片重寫 ffmpeg 指令。

## §4 一鍵流程（人只做一件事）

```
把素材丟到 <inbox>/<n>/ → 說「剪 n」

  1. shorts_autopilot scan <n>
     → 正規化 9:16 ＋ GPS ＋ 接觸表 SHEET.jpg ＋ 招牌/標價牌放大圖 _signs/ ＋ _plan 骨架
  2. 看 SHEET + _signs → 填 _plan（place / what / addr / segs / caps_by_seg）
  3. shorts_autopilot build <n>
     → shorts gate 全項通過才 build → 自動 QA（規格 / LUFS / loop / 字幕對位圖）→ REPORT.md
  4. 看字幕對照圖逐條複核 → 交付
```

**人的操作＝丟素材 + 說一句話**；其餘機械步驟全自動，規則由 gate 擋。
步驟 2 與步驟 4 是**唯二不可自動化**的環節（讀畫面上的字、逐條複核），其他全部該是機械的。

## §5 發布：次要內容軌道 vs 主線

- **次要題材（旅遊/生活/隨手拍）＝獨立軌道**：自然口吻、不套主線 SOP、**不計主線 KPI**（S11）。
  唯一值得做的「優化」＝標題把地名/主體名前置（零成本、不傷真實感）。
- **搜尋型（地標/品名題）**：標題主體名放最前、說明欄含完整地址/規格 → 吃搜尋長尾。
- **推薦型（食物/驚奇題）**：靠首幀近景過續看率關（§1-1）。
- 同一批素材 → **一天發一支做成系列**，置頂留言串下一支。
- 判讀只看續看率（§1-2 三級），**28 天後歸零**（S12）—— 過了 EOL 還在看舊片數據是浪費時間。
