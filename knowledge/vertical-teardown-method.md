# 直式短片逐幀拆解法 — 怎麼量別人的片，以及量出來的一批結果

> **這份檔案的主體是「方法」不是「結論」。**
> §2 是可複製的量測步驟 —— 把它跑在**你自己賽道**的競品上，得到的數字才是你要用的。
> §3 之後是我們用同一套方法量一批樣本得到的結果，附在這裡是為了讓你知道**輸出長什麼樣**、
> 哪些量能看出東西、哪些量看起來很像洞察其實是平台假象。
>
> 樣本已完全去識別：**不會出現任何帳號、店名、地名、商品名、貼文原文或前台互動絕對值**。
> 那些東西是別人的，而且對你沒有用 —— 有用的是量測方法與相對關係。

---

## §1 先讀邊界（不讀這段就會過度推論）

這批樣本 **n=7**：美食 4、開箱 1、AI 工具 2。全部是直式（9:16）、平台上的公開短片。

必須先講清楚的四件事：

1. **全部是「已經成功」的片**，是挑出來拆的。**沒有失敗對照組。**
   → 所以任何一條發現的正確說法都是「**成功的片都這樣做**」，
   不是「**這樣做才會成功**」。要驗因果得自己 A/B。
2. **只有前台可見的互動**（讚／留言／轉發／分享），沒有曝光數、完播率、續看率。
   → 算不出 CTR 等價物，也算不出留存。本檔一律只寫**比例關係**，不寫絕對值。
3. **素材是螢幕錄影**，畫質經過二次壓縮 → 字體筆畫、細節判斷有誤差空間。
4. **響度不可解讀**：整批量到的整合響度幾乎一致，那是**平台正規化**的結果，
   不是作者的選擇。把它寫成「他們都調到 XX LUFS」就是把平台行為當成技巧。
   → 這是拆解最容易產生的假洞察類型：**先問「這個數字是作者決定的，還是平台決定的」**。

n=7 的結論在證據分級上是 **PLAUSIBLE，不是 PROVEN**
（分級體例見 [`viral-playbook-framework.md`](viral-playbook-framework.md)）。
本檔對應的機械規則因此**只做 warn，不擋出片** —— 見 §8。

## §2 怎麼自己做這個拆解（本檔最有用的一節）

目標：把「感覺他們剪得很快」變成**四個可比較的數字** ——
刀速（cuts/min）、刀距分布（中位＋標準差）、換句速率（lines/min）、字幕中位停留（s）。

只需要 `ffmpeg` / `ffprobe`。範例用 bash；PowerShell 請避免對原生 exe 做 `2>&1`。

### 2-0 準備：把片放在單純路徑下

下面用到的 `movie=` 濾鏡會把檔名當字串解析，**Windows 的反斜線與磁碟機冒號都要跳脫**。
最省事的做法是 `cd` 進素材資料夾、只用檔名（`clip.mp4`），不要傳絕對路徑。

### 2-1 片長

```bash
ffprobe -v error -show_entries format=duration -of csv=p=0 clip.mp4
```

### 2-2 刀點（scene detection）→ 刀速與刀距分布

```bash
ffprobe -v error -f lavfi \
  -i "movie=clip.mp4,select=gt(scene\,0.30)" \
  -show_entries frame=pts_time -of csv=p=0
```

輸出就是每個「畫面大幅變化」的時間點。
（舊版 ffmpeg 的欄位名是 `pkt_pts_time`；拿到空結果先換這個欄位名試。）

**門檻 0.30 是起點不是定值**：
- 太高 → 同色調的硬切被漏掉（一盤菜切到另一盤菜，直方圖差異很小）
- 太低 → 手持晃動、推鏡、閃光被當成剪點

**校準方式（必做）**：挑片中任意 10 秒，自己用播放器逐格數一次刀數，
跟同一段的機器輸出對照。差超過 ±1 就調門檻重跑。**沒對照過的數字不要拿去比較。**

### 2-3 換句速率（只對「字幕帶」做變化偵測）

這是整套方法裡最有價值的一步：**把偵測範圍裁到只剩字幕住的那一條**，
畫面怎麼動都不影響，變化就只剩「字換了」。

先找出字幕帶的位置（一次，用眼睛）：

```bash
# 每 0.5 秒抽一格拼成一張接觸表，開圖看字幕壓在畫面高度的哪一段
ffmpeg -hide_banner -i clip.mp4 -vf "fps=2,scale=360:-1,tile=6x5" -frames:v 1 sheet.jpg
```

假設字幕帶落在畫面高度的 62% ~ 80%（高度佔比 18%），就這樣量：

```bash
ffprobe -v error -f lavfi \
  -i "movie=clip.mp4,crop=iw:ih*0.18:0:ih*0.62,format=gray,select=gt(scene\,0.08)" \
  -show_entries frame=pts_time -of csv=p=0
```

- `crop=w:h:x:y` 四個值都可以用 `iw`/`ih` 算相對值 → 換片不用重算像素。
- 門檻要**比刀點低很多**（0.05-0.10）：字幕換句在裁切後的畫面裡是小面積變化。
- `format=gray` 去掉色彩雜訊，讓「文字換了」的訊號更乾淨。
- **前提是字幕位置片內固定** —— 而這件事本身就是量出來的發現之一（§5）。
  遇到位置會跳的片，這個方法不適用，只能人工數。

同樣要做 10 秒手動對照。

### 2-4 語速（有旁白才做）

用 whisper 之類的 ASR 轉逐字稿，**去掉標點與空白**再算：

```
語速 = 字元數 / 片長(秒) × 60
```

中文用「字/分」比「詞/分」穩定。注意 ASR 會補標點，不清掉會高估。

### 2-5 響度（拿來排除，不是拿來學）

```bash
ffmpeg -hide_banner -i clip.mp4 -af ebur128 -f null -
```

讀結尾的 `I:`（整合響度）。**如果整批片的值都擠在同一個數字附近，那是平台正規化**，
代表這個維度沒有資訊量 —— 記下來然後不要再看它（見 §1 第 4 點）。

### 2-6 從時間戳算出四個數字

```python
import statistics as st

def profile(dur, cut_times, cap_times):
    """dur=片長秒數；兩個 list 都是 §2-2 / §2-3 印出來的時間戳（秒）。"""
    gaps = [b - a for a, b in zip(cut_times, cut_times[1:])]
    dwell = [b - a for a, b in zip(cap_times, cap_times[1:])]
    return {
        "cuts_per_min":  round(len(cut_times) / dur * 60, 1),
        "gap_median":    round(st.median(gaps), 2),
        "gap_stdev":     round(st.pstdev(gaps), 2),   # 分布比平均值有資訊量
        "lines_per_min": round(len(cap_times) / dur * 60, 1),
        "dwell_median":  round(st.median(dwell), 2),
    }
```

**為什麼要看標準差**：中位刀距 1.1s 可能是「機械地每 1.1 秒一刀」，
也可能是「0.4s 和 3s 交替」。這兩種片給人的感覺完全不同，只看中位數會混成一種。

### ⚠️ 2-7 這一段的坑（踩過才知道）

- **`-v error` 會吃掉 `showinfo` 的輸出。** 如果你改用
  `ffmpeg -vf "select=...,showinfo" -f null -` 這個寫法，`showinfo` 是走 **stderr 的 info 級別**，
  加了 `-v error` 就一行都不會印 —— 你會得到一個空清單，然後以為這支片沒有剪點。
  上面的 `ffprobe` 寫法沒這個問題（它的資料走 stdout），所以本檔一律用 ffprobe 版。
- **不要拿別人的片做「他一定是這樣想的」推論**。你量到的是**結果**，
  動機是你腦補的。寫結論時把「他刻意…」換成「這支片呈現出…」。
- **前台互動數字要換算成比例再用**（見 §7）。絕對值受粉絲數、發布時間、平台推送影響，
  跨帳號比較沒有意義。

## §2-8 工具版：`src/teardown.py`（把 §2 縮成一個指令）

上面那些指令我封裝成一支工具了。**先讀完 §2 再用它** —— 不然你會拿到數字卻不知道
哪個門檻該校準、哪個數字是平台假象。

```bash
python src/teardown.py <影片檔或資料夾> [--band wide|top|mid|bottom] [--thresh 0.25]
```

一次印出：刀速／刀距分布（中位＋標準差＋最短）、換句速率、
**換句÷剪點**判讀、整合響度，以及（裝了選配套件時）自動抽出的字幕逐字稿。
傳資料夾就整批跑，輸出可直接橫向比較。

**它跟 §2 指令的一個差異**：`cuts()` 走的是 `ffmpeg -vf "select=...,showinfo"` 而不是
§2-7 推薦的 ffprobe 版，因此**故意不帶 `-v error`** —— 帶了會回報 0 刀且完全不報錯。
兩種寫法結果等價；你自己改這段時記得這個地雷還在。

### 依賴分層（缺了只降級，不崩潰）

| 層 | 套件 | 缺了會怎樣 |
|---|---|---|
| **必要** | `ffmpeg` / `ffprobe` | 沒有就量不了，這是整套方法的地基 |
| **選配** | `rapidocr-onnxruntime`（本機實測裝完約 25MB 量級，**不拉 torch/paddle**） | 跳過 OCR 段、印出安裝指令，**節奏量測照跑、退出碼仍是 0** |
| **選配** | `opencc-python-reimplemented` | OCR 照跑，只是不做簡轉繁（抽出的稿會混雜簡體字） |

統計那一半是**純 Python**，完全不需要影片、ffmpeg 或上述選配套件：

```python
from teardown import rhythm_stats, pace_profile
rhythm_stats(cut_times, duration)                  # n / per_min / gap_median / gap_stdev
pace_profile(cut_times, caption_times, duration)   # ratio / driver / 一行判讀字串
```

拿 §2-2、§2-3 那些 ffprobe 指令自己導出的時間戳餵進去也可以。
跑一次看它怎麼判：`python examples/06_teardown.py`（**零素材、零 ffmpeg、零 pip install**）。

### ⚠️ OCR 能力邊界 —— 這段是為了防止你把它用在錯的地方

實測結果：

| 對象 | 準確率 | 可用性 |
|---|---|---|
| **燒錄字幕**（純色／描邊、粗體、無透視） | **0.92 - 1.00** | 可用 |
| **實景招牌／標價牌**（透視、雜背景、藝術字） | **≈ 0**（不是低，是幾乎全錯或零輸出） | 不可用 |

**而且錯的時候信心值仍有 0.85-0.92。**
這句話是整節的重點：**你不能靠拉高 `min_conf` 門檻擋掉錯字**。
門檻只擋得掉「模型自己也知道不確定」的那一類，擋不掉「模型很有把握地讀錯」。

所以這支工具的定位只有一個 —— **把別人已經燒好的字幕讀回來**做競品拆解，
讓 §2 從「逐幀人眼看接觸表」變成「先拿到稿再抽查」。

> 🚫 **不可以拿 OCR 自動生成你自己影片的字幕。**
> 尤其是**品名、價格、規格、人名、地名**這類「錯了就是假資訊」的欄位。
> 那些欄位讀不到就人工看畫面，看不清就**不寫**。
> 機器編出來的錯品名**比沒有更糟**，因為它讀起來像真的 ——
> 這跟 [`meta-lessons.md`](meta-lessons.md) 的「不編造數字」是同一條原則的兩個面向，
> 也跟 §10「這是實績，還是推算？」是同一個問題。
> 拆解別人的片：OCR 輸出是**草稿**。做自己的片：OCR 輸出**不是素材**。

簡繁混雜是 OCR 模型的字典偏誤，`opencc s2twp` 可修掉約 **8 成**；
剩下的是真誤認，**特徵是「字看得懂但湊起來不成句」**，人工複核抓得到 —— 所以要複核。
工具的輸出每次都會印一行提醒，那行不是客套話。

### 兩個靜默失敗（工具裡已經修掉，但你自己改的時候會重新踩到）

- **窄字幕帶會靜默漏掉整段字幕。** 預設 `--band wide` 而不是精準窄帶，是因為實測發現
  **字幕位置在片內會移動**（某支樣本 t=6s 在畫面高度 24-27%、t=12s 掉到 30%）。
  用窄帶不會報錯，你只會覺得「這支片字幕比較少」。
  （這也是 §5「位置片內固定」那條的邊界：**多數片固定，但別假設全部**。）
- **近似重複判定要用順序敏感的比對**（`difflib`），不要用「字元集合重疊率」。
  中文常用字（的／了／是／我）到處都有，集合法會把不同句子判成同一句 ——
  第一版就是這樣寫的，一支 22 條字幕的片只抽出 9 條，**而且不會報錯**。

## §3 最重要的一個發現：節奏主體是「換句」不是「剪點」

七支樣本的量測結果（A-G＝匿名代號；類型只標題材大類）：

| 樣本 | 題材 | 片長 | 刀/分 | 中位刀距 | 刀距標準差 | 換句/分 | 中位停留 |
|---|---|---|---|---|---|---|---|
| A | 美食・走動 POV（唯一有旁白） | 54.3s | 30.9 | 2.00s | 0.91 | 39.7 | 1.43s |
| B | 開箱・靜態商品特寫 | 31.8s | **9.4** | 5.54s | 3.42 | **75.4** | **0.73s** |
| C | 美食・特寫巡禮 | 24.5s | 51.5 | 1.10s | **0.03** | 71.1 | 1.07s |
| D | 美食・賣場巡禮 | 30.1s | 35.8 | 1.47s | 0.45 | 59.7 | 1.03s |
| E | 美食・餐桌 | 22.9s | 52.4 | 1.17s | 0.32 | 57.6 | 1.17s |
| F | AI 工具・人物＋螢幕錄影 | 35.2s | 20.4 | 1.90s | 1.53 | 75.0 | 0.77s |
| G | AI 工具・螢幕錄影＋貼紙字卡 | 33.4s | 25.1 | 2.02s | 0.45 | 52.0 | **0.63s** |

**7/7 的換句速率都高於刀速率。** 倍數從 1.1× 到 8.0×。

最極端的是 B：**32 秒只有 5 刀**（中位刀距 5.5s，其中一段長達 12.4s），
但字幕換了 40 次。整支片的推進感**完全由文字承擔**，畫面幾乎是靜態商品特寫。

**可直接用的結論**：素材不夠、拍不到多角度、手邊只有一顆長鏡頭時，**不要硬切** ——
把節奏交給字幕，一句 0.7-1.2s 連續推進，觀感一樣不拖。
這比「素材不夠就重拍」實際得多。

**資訊型比生活型更極端**：F、G 兩支的刀速最低（20-25 刀/分，因為螢幕錄影亂切就看不懂操作），
換句速率卻是全批最高的一組。→ **螢幕錄影不要靠剪，靠字卡推**：一個操作一張卡。

## §4 三種節奏原型（用刀距分布區分，不是用感覺）

**A 型 · 節拍鎖定**（樣本 C、E）— 中位刀距 1.07-1.17s，**標準差 0.03-0.32**
C 的全部間隔落在 1.03-1.17s 這個極窄帶裡 —— 這是**卡 BGM 節拍**的機械級剪法，不是手感。
用途：菜色巡禮／商品陣列。每刀一個項目，靠規律感堆出「量很多」的印象。

**B 型 · 敘事弧**（樣本 A）— 中位 2.00s，標準差 0.91，且有明顯結構：

```
開場 1.5-2.3s（建立場景）
→ 中段 1.0s ×5 連打（爆點）
→ 後段 2.0-3.0s（回到敘事，逐項介紹）
→ 收尾 4.6s（最長的一刀，收）
```

**慢 → 爆 → 穩 → 收**。這是全批唯一有旁白的一支，刀距跟著語意走而不是跟著節拍走。

**C 型 · 靜態＋文字驅動**（樣本 B、F、G）— 刀距長且標準差大（1.53-3.42），
節奏全部由字幕承擔。見 §3。

→ **先決定原型再開剪**：想清楚這支是「規律感」還是「敘事弧」還是「文字推進」，
刀距分布自然就定了。反過來（先剪再看感覺）就是每支片節奏都不一樣的原因。

## §5 字幕系統：三條可直接抄的規則

**位置：片內固定，避開平台 UI。**
七支的位置並不統一（頂部／底部／中下都有），**但沒有任何一支在片內跳位**。
→ 沒有「唯一正確的位置」，只有「選定就不准動」。
底部型全部壓在畫面高度 64-70% 之間 —— 再低就會被平台的帳號列／按鈕蓋掉。
**先確認你的目標平台把 UI 畫在哪，再決定字幕帶。**

**字體：由「背景亂度」決定，不是由好不好看決定。** 這是本批最反直覺的一條。
- 背景乾淨（棚拍／特寫／靜物）→ **明體/宋體＋寬字距**，吃質感。
- 背景亂（走動 POV／現場／人多）→ **粗黑體＋厚外框**，保可讀性。
  樣本 A 是走動 POV，字幕沒有外框就會被背景吃掉。
→ 所以「該用哪個字體」不是品味題，是**先看背景**的判斷題。

**顏色：底一律白，只有「感官 payoff 詞」上第二色。**
七支的字幕主色全部是白。整批只出現過一次第二色，上色的是一個**感受詞**（形容口感的那個詞），
不是名詞、不是隨機、不是整句。
→ 這正是 [`shorts_gate.py`](../src/longform_maker/shorts_gate.py) 的 **S-I white-first**
（非白字比例上限＋顏色種類上限）在外部樣本上的佐證。

**價格／關鍵數字獨立成大字，不寫進句子。**
樣本 D 的價格是獨立的超大字（佔畫面寬度約三分之一），與敘述句分層。
→ 數字要被看見就別混在句子裡。同理適用於規格、版本號、期限。

## §6 貼文結構：五種原型的骨架

⚠️ 以下是**結構描述**，不是任何一篇貼文的原文 —— 原文是作者的著作，
這裡只寫「它由哪些功能區塊組成、每區塊放什麼句型」。照骨架寫你自己的內容。

**6-1 人設短句型**
```
[第一行：立人設的短句]        ← 不是「大家好」、不是主體名
[反向價值錨定：同樣的錢在別的地方買不到什麼]
[具體名詞堆疊 ×3-5]           ← 用真實項目名，不用「應有盡有」這種空詞
（空行）
[完整價目 / 規格 / 限制條件]   ← 連時間限制這種掃興資訊都寫，因為可執行
（空行）
[主體名]
[地址 / 連結]
```
這型的關鍵：**同一個 hook 在旁白第一句、畫面第一句字幕、貼文第一行三處復用。**
本批有兩支明確這樣做（其中一支甚至把同一個 hook 換句話說了兩次）。

**6-2 促銷條列型**
```
[極限宣稱 ＋ 一個數字]
[痛點解決]
[加值服務]
[無門檻聲明]
[分享 CTA]
—
[分店/型號 1：名稱 / 地址 / 時間 / 電話]
—
[分店/型號 2：…]
```
規則：**一行一賣點**；emoji 只放句尾不放句中；排序是「宣稱 → 痛點 → 加值 → 無門檻 → CTA」。

**6-3 長文導覽型**
```
[標題行，前後用符號框起來 ＋ 分類 hashtag]
[定位：離知名地標走路 N 分鐘 ＋ 一句話定義這是什麼]   ← 比純地址好懂，值得抄
[招牌項目 1：「品名 $價格」＋ 為什麼 ＋ 感受描述]
[招牌項目 2：…]
```

**6-4 同好共感型（開箱）**
```
[品類 ＋ 商品線 ＋「開箱」＋ （附帶品）]
（空行）
[只有圈內人懂的期待句]
[為什麼這件事值得講]
…
[提問 CTA：把選擇題丟給讀者]     ← 導留言，不是導分享
（空行）
[hashtag ×4，中英混排]           ← 中英各吃一邊的搜尋
```

**6-5 短行斷句型**
```
[修辭問句開場：預設答案是「沒人不…」]
[一句感受 ＋ 句尾 emoji]
（空行）
[意外性框架：先說本來不知道，再說結果居然有 —— 把推薦包裝成意外發現]
[過程 ＋ 把感受換算成可想像的行為量]   ← 換算勝過形容詞（見 §9 第 14 條）
[借第三方權威背書]
```
特徵：**每行 6-15 字，一行一個資訊點**，排版像詩不像段落。

**貼文長度由 CTA 的位置決定**（這條最實用）：
- CTA 在**影片內**（例如引導留言關鍵字）→ 貼文只留情緒句 + hashtag，兩三行就夠。
- CTA 在**貼文內**（引導標記朋友／看說明欄）→ 貼文才是主要載體，該長就長。
- 別無條件寫長文，也別無條件寫短。**先問 CTA 在哪。**

更多 caption 句型 → [`ig-caption-patterns.md`](ig-caption-patterns.md)。

## §7 互動結構：這個品類的主要動作是「傳給朋友」

有三支能看到完整前台互動。換算成比例（絕對值刻意不列，跨帳號沒有可比性）：

- **三支的分享數都超過按讚數**（分享÷讚 > 100%）。
- **留言率全部 ≤1.5%**（留言÷讚）。
- 轉發（公開轉貼）遠低於分享（私訊傳送）。

而其中一支的貼文**直接寫著要讀者傳給朋友** —— 這不是意外，是設計出來的：
內容為了「值得傳給某個特定的人」而寫，CTA 也明說。
反觀開箱那支用提問 CTA 導留言，目標本來就不同。

**可直接用的結論**：
- 探店／優惠／情報類 → 寫**分享 CTA**，而且內容要能回答「為什麼要傳給他」。
  把傳播動作包裝成「你在幫某個人的忙」，比直接下命令要對方轉發來得軟。
- 開箱／觀點類 → 寫**提問 CTA** 導留言。
- **別預設按讚是主要指標** —— 這個品類按讚是最弱的訊號。
- 收藏型 CTA 埋**中段**比放結尾好，理由給的是「之後要用時找不回來」這種即時損失，不是請求。

## §8 平台差異：把死區規則跨平台套用會做出「假 BLOCK」

[`shorts-mastery-2026.md`](shorts-mastery-2026.md) 的 S8 寫「26-44s 是片長死區」。
那條的來源是 **YouTube Shorts** 的第三方研究。本批樣本是 IG / FB 的直式短片，
其中**兩支（31.8s、30.1s）正好落在該區間，表現正常**，其中一支還是全批互動最高的。

→ **死區規則不可跨平台套用。**

這件事的教訓比這條規則本身重要：**一個會擋掉好片的閘門比沒有閘門更糟**，
因為你會信任它，然後照著它改壞你的片。所以：

- [`shorts_gate.py`](../src/longform_maker/shorts_gate.py) 的片長帶改成**平台感知**：
  `spec["platform"]` ∈ `yt_shorts` / `ig_reels` / `fb_reels`，
  平台只提供**預設值**，`rules={...}` 仍可逐項覆寫且優先；平台名打錯直接擋，不靜默 fallback。
- §3 的換句速率落成 **S-O**，而且**只 warn 不 fail** —— 理由見 §1：
  樣本全是成功片、沒有失敗對照組。**不確定的知識就做成 warn**，
  把數字報給人看（`cap_rate` / `cap_dwell`），讓人決定，不要替人決定。

跑一次就懂：`python examples/04_shorts_gate.py`
（同一支 31s 的片：預設被擋 → 換你的門檻放行 → 只改平台也放行）。

## §9 可抄清單（18 條）

**節奏**
1. 素材只有長鏡頭 → **節奏交給字幕**（0.7-1.2s 一句），不要硬切
2. 項目巡禮 → **卡 BGM 節拍固定 1.0-1.2s 一刀**，規律感本身就是「量很多」的訊息
3. 有旁白 → 刀距跟語意走，做「慢 → 爆（1.0s 連打）→ 穩 → 收（最長刀）」的弧
4. **螢幕錄影不要靠剪，靠字卡推**：一操作一張卡、0.6-0.8s 一換
5. 開剪前先選定節奏原型（§4 三選一），不要剪完才看感覺

**字幕**
6. 字幕位置**片內絕不跳**，且避開平台 UI（底部型壓在畫面高度 64-70%）
7. 背景亂 → 粗黑體＋厚外框；背景乾淨 → 明體＋寬字距。**看背景，不是看喜好**
8. 底色一律白，**只有感官 payoff 詞上第二色**
9. **價格／關鍵數字獨立大字**，不寫進句子
10. 標題卡可以整支常駐（本批有一支從 0 秒掛到片尾，等於永遠有識別）

**用詞與包裝**
11. 貼文第一行＝立人設或修辭問句，**不要主體名、不要「大家好」**
12. 價值錨定用**反向對照**（這個錢在別的地方買不到什麼）
13. 定位用**「離地標走路 N 分鐘」**，不是只給地址
14. **把感受換算成可想像的行為量**（配幾碗飯／撐幾天／省幾小時），不要用形容詞
15. **同一個 hook 在旁白／畫面首句／貼文首行三處復用**

**CTA**
16. 探店/情報類寫**分享 CTA**；開箱/觀點類寫**提問 CTA**
17. 分享 CTA 用「做好事」框架比命令句軟；收藏 CTA 埋中段不放結尾
18. **貼文長度由 CTA 位置決定**：CTA 在影片內 → 貼文只留情緒+標籤；CTA 在貼文 → 貼文是主載體

## §10 拆解時一定要問的一句話：這是實績，還是推算？

本批有一支的內容是「用某個工具能賺多少錢」。逐幀看下來，那個金額是這樣長出來的：
拿**別人**的極端案例觀看數 → 打開某個 MCN 行銷頁上的展示用單價 → 開計算機相乘 → 換匯 → 口播成結論。

**全片沒有一秒是他自己的收益後台。** 標題卡甚至自己就掛了一個但書，明說作者本人也還在試。

四個破綻，每一個都對得到畫面：
- 沒有任何一手憑證，全部是**套公式的假設值**
- 單價取自**行銷頁的最佳情況**，不是常態
- 用**極端案例**當「普通人也能做到」的基準（倖存者偏差）
- 結尾導私訊收名單 —— **收益故事是誘餌，漏斗才是目的**

這正好是 [`meta-lessons.md`](meta-lessons.md) **M107（上鏡數據只用真後台截圖，禁自繪重建）**
的反面教材，而且值得想清楚：**這個手法是有效的**，因為觀眾分不出「推算」與「實績」。
所以 M107 不是效果考量，是**誠信選擇** —— 選它就是主動放棄一個確實有效的手法。

→ 拆解別人的片時，看到任何數字都先問一句：**這是實績，還是推算？**
   自己做內容時，下次有人說「這樣比較有說服力」，問同一句。

**可以抄的（與宣稱無關的結構）**：自我實驗框架（標題明說自己也還在試，降低推銷感）／
標題卡常駐／用螢幕錄影當過程證明／連續三個否定式消除門檻（不必具備 X／不必做 Y／連 Z 都不用）／
情緒最高點用排版方向（直排大字）而不是只放大字級。

**不准抄的**：把推算當實績、拿極端案例當基準、用行銷頁最佳值當常態。
