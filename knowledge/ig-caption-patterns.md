# IG Reels Caption 模板庫（旅遊+美食類 caption 結構）

> 來自 video-autopilot-kit 開源知識庫 · MIT 授權

> 用途：寫 IG Reels caption 時自動載入；搭配主 playbook 的 INSTAGRAM REELS 區

---

## 三種 Archetype 對比

| 維度 | A. 景點打卡 | B. 美食探店敘事 | C. 菜單+評分系統 |
|---|---|---|---|
| Caption 長度 | 中（資訊密集） | 長（敘事體驗） | 長（菜單+逐菜評） |
| 第一人稱 | 少 | 多 | 多 |
| 情緒 | 客觀 / 嚮往 | 主觀 / 共鳴 | 權威 / 推薦 |
| Hashtag | 4 個（含英文國際） | 5 個（地理+品類） | 5 個（含系列 hashtag） |
| 結尾錨 | Plus Code 座標 | 營業時間 | 🏠⏰☎️🗾🚇 emoji 圖標分行 |
| 目標 KPI | **Save**（收藏） | **Comment + DM share** | **Save 極致**（高 Save/Like 比） |
| 系列 brand asset | 無 | 影片字卡（系列標題） | 你自己的視覺評分符號 + 系列 hashtag |

## Archetype A：景點打卡

### 數據觀察（本檔不刊任何帳號的實測數字）

> ⚠️ 本檔只給 **caption 結構**，不刊任何帳號（自己的或別人的）的 like / save / 觸及數字。
> 別人的帳號數據不是我們能代為公開的東西；自己的數據請留在 `profiles/`（gitignored）。
> 要驗證下面的相對強弱，請發**你自己的**貼文，用你自己的 Insights 排序。

| 帖型 | 相對 Save/Like（自行量測欄） |
|---|---|
| 單點絕景打卡 | `<fill in>`（通常是三型裡最低的） |
| 多景點清單型 | `<fill in>` |
| 步道／路線絕景型 | `<fill in>` |

**洞察（方向性，不附數字）**：
- 清單型（多景點打包）+ 絕景型的 Save/Like **明顯高於單點打卡型** —— 因為「之後要照著去」需要收藏，單張美照不需要
- Hook 觸發詞：「最美的」「不可思議的」「你聽說過」→ 直接撩 save 衝動
- Save 越高 → IG 越擴推（save = 強烈 intent 訊號，2025-2026 演算法重點）
- ⚠️ 上表填完先看**排序**再看絕對值：跨帳號比絕對 Save/Like 沒有意義（受粉絲組成/題材/發布期影響）

### Caption Anatomy

1. **一句 hook**（caption 主文，貼在 username 旁）— 撩起好奇 / 嚮往
2. 📍 **中文地名**（縣市。具體景點）
3. **English location 一行**（國際 reach + SEO）
4. **背景/規格**（歷史 / 長度 / 工法 — 2-3 行）
5. **特色亮點**（一句拉重點）
6. **限制提醒**（什麼不能做 / 時間）
7. **實用區**（`□` 或 `- ` 條列）：開放時間 / 地址 / Plus Code
8. **Hashtag 一行 4 個**：`#縣市景點 #具體地點 #別名 #英文縣市`

### Template Skeleton

```
{一句 hook — 嚮往型形容詞 + 主體，10-15 字內}

📍 {縣市}。{景點}

{English Location Name}

{背景/規格 2-3 行}

{特色亮點 1-2 行}

{限制提醒 1-2 行}

開放時間：{HH:MM-HH:MM，季節變動}
-
□ 地址：{完整地址}
□ 座標：{Plus Code} {里} {縣市}

#{縣市}景點 #{地點} #{別名} #{english_city}
```

> **連 hook 那一行都不要照抄別人的原句** —— 一句完整的 caption 原文貼進搜尋框就能找回原貼文，
> 而原貼文帶著店名、地址與座標。示意文只示範「句型」，實際字句自己寫。

**樣本 1：水圳景點（資訊密集型）**
> {嚮往型 hook，句型＝形容詞 + 主體特徵}
>
> 📍 {縣市}。{水圳景點}

> 目前只開放{可進入的區段}
>
> 開放時間：{HH:MM-HH:MM，季節變動}

**樣本 2：多景點清單型**
> {疑問句式 hook，把整個區域當主體}

**樣本 3：濱海步道絕景**

> □ 座標：{Plus Code} {里} {縣市}{區}
> #{縣市}景點 #{步道} #{地名} #{english_city}

## Archetype B：美食探店

### Caption Anatomy

1. **影片開頭字卡**（系列感標題）— 帳號 brand asset，格式：「{你自己的系列名} - {該集副標} -」<br>⚠️ 系列名自己取，不要沿用別的帳號在用的那一句 —— 系列名就是對方的識別
2. **影片內 text overlay 標重點**（例：「{一句空間或餐點的重點}」）— 對應 caption 內容，給靜音觀眾完整資訊
3. **BGM 標註**（音樂選曲，IG 自動顯示）— 強化氛圍
4. **開場定位**（店名 + 一句場景）— 例：「{區域}大名店『{店名}』」
5. **體驗敘事**（第一人稱長段）：
   - 環境氛圍
   - 餐點細節 + 價格
   - 服務互動（具體動作，不只形容詞）
   - **中肯結論**（好+壞都寫 — 真實感是訊號）
6. **結尾 emoji + 真誠評語**（多用 😂）
7. 📍 **店名 + 地址 + 營業時間**
8. **Hashtag 一行 5 個**：`#縣市 #縣市美食 #縣市美食地圖 #縣市晚餐 #區域美食`

### Template Skeleton

```
{店名 / 一句場景定位}
{營業特色 / 客流 hook}（例：{營業日限制} / 餐期一堆人在等）
{空間描述}（例：{樓層或座位型態的差異}）
{餐點細節 + 價格}（例：{主餐內容} + 價格）
{服務互動描述 — 越具體越好}
（例：{店員主動做的某個動作} / 老闆會問你有沒有吃飽）
{中肯結論 — 好+壞都寫}
（句型：{餐點的中性評價} + 但 + {過程/氛圍的正面評價}）{emoji 😂}

📍 {店名}
•{地址}
•{營業時間}

#{縣市} #{縣市}美食 #{縣市}{餐種} #{縣市}晚餐 #{縣市}餐廳
```

### Reference Quotes（已泛化為示意樣本）

> ⚠️ 下面兩則是**用骨架填佔位符生成的示意文**，不是任何真實貼文的轉錄。
> 具體的店型、營業日、樓層配置、餐點內容一律留成 `{}` —— 這些細節單獨看都很普通，
> **湊在一起就足以反查到一家實體店**（承 Archetype A 的同款教訓）。
> 同理 **句子本身也不要照抄**：一句原文貼進搜尋框就找得回原貼文，而原貼文帶著店名和地址。

**樣本 1：坐下來慢慢待型**（合成示意，非真實貼文）
> {地區}的{老字號店型}，{營業時段特色}
> 適合跟朋友來{主要活動}的地方
> {環境評價一句} + {該店的一個體驗點}
> {老店的缺點一句（設備／裝潢／動線）}，但{氛圍的正面評價}
> {餐點評價一句：價格帶 + 味道}，{餐點種類}都有
> {一句誠實的來訪動機}{emoji 😂}
>
> 📍 {店名} • {完整地址} • {營業時間}
> #{縣市} #{縣市}美食 #{縣市}下午茶 #{縣市}晚餐 #{縣市}餐廳

**樣本 2：互動式共食型**（合成示意，非真實貼文）
> {區域}的人氣店「{店名}」
> {營業日限制}，{客流 hook 一句}
> {座位或樓層配置}
> 有多種{主餐}可選，附{配菜形式}，價格約 {價格}
> {入座後店家主動做的動作}
> {店家的第二個互動細節}
> {中肯結論：餐點中性 + 過程正面}{emoji 😂}

### 關鍵成功因子

- 🔑 **不假裝萬物皆讚** — 敢寫「這道普通」「這裡偏貴」反而推升信任
- 🔑 **互動細節 > 形容詞** — 寫出店家實際做的那個動作，比「服務很好」有畫面 100 倍
- 🔑 **系列感字卡** — 一個固定的系列名 = 帳號 brand asset，每篇連動（名字自己取）
- 🔑 **影片內 text overlay** 對應 caption 重點 — 給靜音觀眾完整訊息

## Archetype C：菜單+評分系統化

### 數據觀察（本檔不刊任何帳號的實測數字）

> ⚠️ 同 Archetype A：不刊任何帳號的實測值。這型的特徵是 **Save/Like 比高到不像話**
> （收藏的人可以多過按讚的人 —— 因為菜單+評分是「下次點餐要用」的工具，不是「看過就好」的內容）。
> 你自己的量測欄：Save/Like `<fill in>`。

⚠️ **這型的天花板明顯高於另外兩型** — 菜單+評分+結構化地址 = Save 神器極致版；但**別把別人的極端值當成你的目標**，先量你自己的三型排序

### Caption Anatomy

1. **權威 hook**：**行為**證據，不是形容詞（你為這家店做過什麼／做過幾次，比「好吃」有力）
2. **發現故事**：怎麼找到的 —— 帶出 in-group 信任（不是隨便滑到的）
3. **平價+品質 + emoji 強化**（你自己的 emoji）
4. **結論前置**：先給結論，而且是**會改變往後行為**的那種（給 save 一個強動機）
5. **菜單列表**（你自己的列點符號，列點 5 項）
6. **視覺評分**：用**你自己的評分符號**（例：★ 或自選圖示）— **評分系統 = 你的 brand asset，可重複收藏**
7. **逐菜評論段 + emoji 強化**（你自己的 emoji）— 每道一段
8. **權威排序**：把這家放進你自己的排行裡（「我心中的第幾名」型）— 信任拉滿
9. **結構化店家資訊**（emoji 圖標分行 — 視覺易讀 +5x）：
   - 🏠 店名
   - ⏰ 營業時間（公休日）
   - ☎️ 電話
   - 🗾 地址
   - 🚇 最近的交通站點
10. **分店補充**：（其他區也有分店）
11. **Hashtag 含系列**：`#{帳號系列 hashtag} in {地區}` + 4 個地理品類
12. **協作 tag**：圈朋友拓散，雙池推播

### Template Skeleton

```
{權威 hook — 行為證據型：{你為這家做過的行為} + {次數/頻率}}
{發現故事 — 怎麼找到的}
{平價/品質一句 emoji 強化} {你自己的 emoji}
{結論前置 — 給 save 強理由}
-
{列點符號}{菜名1} {列點符號}{菜名2} {列點符號}{菜名3} {列點符號}{菜名4} {列點符號}{菜名5}
整體美味程度：{你自己的評分符號}（例：4.5/5）
{逐菜評論段，每道一段 + emoji}
{權威排序 — 把這家放進你自己的排行：「我心中的第 N 名」}

🏠：{店名}
⏰：{營業時間}（{公休日}）
☎️：{電話}
🗾：{完整地址}
🚇：{最近的交通站點}
（{分店補充}）
-
#{帳號系列 hashtag} #{店名} #{縣市}{餐種} #{縣市}{菜系} #{區}美食
```

### 關鍵成功因子

- 🔑 **回訪次數 hook** — 寫「我回訪了幾次」比寫「好吃」強 100 倍（行為證據 > 形容詞）
- 🔑 **視覺評分系統** = 你自己的 brand asset，每篇連動 → 變 collectible content
- 🔑 **菜單+評分+地址完整** = save 後可直接行動，極大化 save 動機
- 🔑 **系列 hashtag** = 帳號內部 archive，粉絲可一鍵看全
- 🔑 **emoji 圖標分行** = 比純文字易讀 5 倍（IG 算法的視覺停留時間訊號）
- 🔑 **協作 tag** = 雙帳號推播池，觸及非粉絲

## Cross-Pattern 共同點

- 📍 開頭固定地點 emoji（IG 用戶習慣訓練成功）
- 都用「換行分塊」破閱讀牆
- BGM 沉浸式氛圍音（不靠口白）
- Caption 主文（username 旁那行）= 第二個 hook，必定 ≤15 字

## 應用到自己的頻道（依內容類型對位）

- **旅遊 Vlog Reels** → 套 **Archetype A**（如有座標習慣可保留 Plus Code）
- **工具/技巧體驗 Reels** → **Archetype B** 變體：
  - 標題字卡保留（「{主題} 系列」系列感）
  - 體驗敘事 → 改「我用 X 做 Y 遇到什麼」
  - **不要套「正反評價」公式到工具教學** — 工具沒踩坑就不寫缺點，硬寫變假
- **強推薦類教學 / 軟體評測 / 課程介紹 Reels** → **Archetype C**（Save 神器）：
  - 套你自己的視覺評分符號變 brand asset
  - 用 ◆ 列點功能/重點 5 項
  - emoji 圖標分行（🏠 軟體名 / ⏰ 學習時數 / 💰 價格 / 🔗 連結 / 🎯 適合誰）
  - 系列 hashtag：`#{你的系列} in {領域}` 或類似
- **教學頻道 Shorts repurpose** → 套 A 的清單型（save 神器）：「3 個 {軟體} 你不知道的功能」
