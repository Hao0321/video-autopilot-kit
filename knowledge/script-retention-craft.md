# Script Retention Craft — 觀眾語言＋留存節奏（腳本三支柱的後兩柱）

一份腳本可以用三個**互相獨立**的方式壞掉：

| 支柱 | 失敗長什麼樣 | 住在哪 |
|---|---|---|
| 1. **語氣** | 稿子很順，但**不像你**寫的（AI 味 / 通稿味） | [`script-style-framework.md`](script-style-framework.md)＋[`../templates/style_profile.template.md`](../templates/style_profile.template.md) |
| 2. **觀眾語言** | 像你，但**路人聽不懂**（行話、英文詞、內部黑話） | 本檔 §1（機械層 = `script_gate.check_audience_language`） |
| 3. **留存節奏** | 聽得懂，但**看不下去**（沒懸念、拖、流水帳） | 本檔 §2（機械層 = `script_gate.check_rhythm` + `interrupt_schedule`） |

三者可以各自壞。**只修語氣不會救留存，只修留存不會讓觀眾聽懂。**
錄音前跑 [`../src/longform_maker/script_gate.py`](../src/longform_maker/script_gate.py) 的 `gate(text)`：
觀眾語言 fail 級（擋稿）／節奏 warn 級（逐條人工過目）。
本檔收的是**機械擋不了、寫稿當下要人工套的 craft**——gate 只能問「有沒有」，問不了「好不好」。

> ⚠️ 本檔所有數字（60-90 秒、45 秒、35-40 字、20-25%…）都是**啟發式起始值**，
> 不是量測常數。它們的用途是給你一個「明顯偏離就會被抓出來」的預設，
> 然後**用你自己的留存曲線校準**（改哪個門檻 → `script_gate.py` 頂部的常數區）。
> 字速前提：中文口播約 240-280 字/分（gate 預設 260）——先用你自己的舊片量一次真實字速再信這條。

## §1 支柱 2：觀眾語言（旁白層）

### 鐵則

**旁白只准出現兩種詞：路人 0.5 秒懂的，或你自己樣本已經驗證過的。**
（包裝層——標題／縮圖／前 3 秒——比這更嚴，那是另一套規則。）

行話的傷害不是「觀眾覺得你炫技」，是**觀眾停下來解碼**。0.5 秒的解碼停頓在留存曲線上就是一個小凹陷；
連續三個行話 = 一個跳出點。

### 四層詞表（機械執行）

| 層 | 意義 | gate 行為 |
|---|---|---|
| `SPOKEN_OK` | 你舊稿實際講過、影片留存正常 → 可直接講 | 放行 |
| `SUBSTITUTE` | 你本來就有中文說法的英文詞 | **fail**，提示你講中文版 |
| `NEED_PAIR` | 可以講，但同一個 beat 要有白話同伴詞 | 無同伴詞 → **fail** |
| `HARD_BAN` | 內部工程詞，旁白永遠不出現 | **fail** |
| （不在表上） | 新詞 | `lang.unknown_term` **warn** → 人工判級 → 入表 |

**四層表隨 kit 出貨是空的，這是刻意的。** 別人的白名單帶著別人的題材（他的觀眾聽過的詞 ≠ 你的觀眾聽過的詞）、
別人的市場（有些平台名只在特定地區通用）、別人的語感。照抄別人的表 = **用別人的觀眾檢查你的稿子**，
比不檢查更糟——它會放行你觀眾聽不懂的詞、又擋掉你觀眾早就熟的詞，而你還會信任它。

四表全空時 gate 不掃詞，只回一條 `lang.no_vocab` warn，稿子照樣過得去。
先讓流程跑起來，再慢慢把表養大。

### 怎麼從自己的樣本建這四層表（一次 30-60 分鐘）

1. **備料**：把你手上全部舊片的逐字稿（ASR 轉的就行，錯字不影響）丟進一個資料夾。**沒有逐字稿就先轉——這一層沒有捷徑。**
2. **抽 token**：用正則掃出所有拉丁字母片段（`[A-Za-z][A-Za-z0-9+#.-]*`），統計**出現在幾篇**（不是幾次——一篇裡講 20 次可能只是那支的主題）。
3. **`SPOKEN_OK` = 出現 ≥2 篇的那批**，人工刪掉口誤與一次性專有名詞。這一層是「觀眾已經買單過」的證據，不是你覺得他們懂。
4. **`SUBSTITUTE` 用反向法找**：列出你**寫稿時手會自動打英文**的詞，回頭查逐字稿——如果你講話時 100% 都是講中文版，它就屬於這層。
   這是最容易漏、傷害卻最大的一層：用英文版會**同時**掉語氣（不像你）與觀眾語言（路人聽不懂），一次踩兩柱。
5. **`NEED_PAIR` = 你圈內人都懂、圈外人要想一下的詞**。value 填「你講得出口的白話同伴詞」清單（同 beat 出現任一個就算過）。
6. **`HARD_BAN` 最好填**：打開你的終端機歷史、專案 README、工具參數表——那些只有你和機器在講的詞，全部丟進來。
7. 存成 `audience_vocab.json`（骨架 → [`../templates/audience_vocab.example.json`](../templates/audience_vocab.example.json)），
   在腳本流程裡 `load_vocab("你的路徑")`。

**判級的唯一標準：不是「我的同溫層懂不懂」，是「我樣本裡講過沒有＋路人 0.5 秒懂不懂」。**

### 術語消化的六個句式（寫稿時直接套）

不是「不准講術語」，是**講了就要當場消化掉**。六種都能過 `NEED_PAIR` 的同伴詞檢查：

1. **術語 → 超白話翻譯**：「<術語>……講白了就是<一句大白話>」
2. **白話現象 → 最後才命名**：先描述觀眾看得到的現象，最後補一句「這個過程就叫做<術語>」（教學定義式，資訊在前、標籤在後）
3. **英文功能名 ＋ 括號中譯 ＋ 它能幹嘛**：「<Feature>（<中譯>）……可以讓你<具體結果>」
4. **冷門詞 → 降級成一個效果**：「<冷門詞>就是一種<看得到的效果>」，把陌生名詞降成一個現象／一個類別
5. **縮寫 → 類比收尾**：「<縮寫>……有點像<觀眾熟悉的東西>」
6. **平台黑箱 → 拆成「時間 ＋ 條件」兩層**：「<機制>大約在<時間點>發生……主要看<兩三個條件>」

一個實用副作用：這六式全都**自帶白話同伴詞**，所以你照套就不會被 `lang.jargon_unexplained` 擋。

### 反向鐵證法（找出你的 `SUBSTITUTE` 嫌疑犯）

在逐字稿裡**出現 0 次的英文詞，就是嫌疑犯**——你講話時從來不用它，寫稿時卻打得很順手，
代表那是「打字的你」不是「說話的你」。這種詞念出來一定卡。

同場加映一個常見邊界：多數人的英文停在**單詞層級**（bug／OK／hook 這種）。
一旦你的稿子出現**整句英文或英文子句**，幾乎都是寫稿時偷懶的訊號——先查逐字稿，你大概從沒那樣講過話。

## §2 支柱 3：留存節奏

### 已經機械化的（`script_gate` 自動跑，別再靠記憶）

| 規則 | gate 標籤 | 級別 |
|---|---|---|
| Cold open：前兩段禁自介／打招呼、第一段要有結果詞 | `hook.banned_opener` / `hook.no_result_word` | fail |
| Hook 要有懸念訊號（open loop） | `rhythm.hook_no_open_loop` | warn |
| Interrupt（問句／數字／轉折）最大間距 ≤90s | `structure.interrupt_gap` | warn |
| Re-hook 落點 25% / 50% / 75% 自動排程 | `interrupt_schedule` | 資訊 |
| 單一 beat ≤45s，超過要有新 payoff 或拆開 | `rhythm.beat_too_long` | warn |
| 每個中段 beat 要有動能詞或問句 | `rhythm.no_momentum` | warn |
| 前段禁總結感詞（總之／以上就是／回顧一下 只准片尾） | `rhythm.mid_closing_tone` | warn |
| 長 beat 全是長句 = 沒打點 | `rhythm.no_punch` | warn |
| 段首「然後／接著／再來／另外」>2/min = 流水帳 | `rhythm.andthen_chain` | warn |
| 每章至少一個問句 ＋ 結尾 CTA 齊全 | `structure.chapter_no_question` / `structure.outro_*` | fail |

### 人工 craft（gate 驗不了，寫稿時自己套）

1. **Hook 三件套（前 15 秒內做完三件事）**：① 確認點擊——用一句重述標題的承諾，讓點進來的人知道沒點錯；② 開一個 curiosity loop；③ 一句 credibility（你憑什麼講）。
   **hook 永遠等正文寫完才回頭寫**——先寫 hook 會逼你把承諾寫大，然後正文兌現不了。
2. **Hook 一句一拍**：hook 段用短打（中文約 ≤15 字一拍），不要用 30 字長句開場。開場的節奏就是全片節奏的樣本。
3. **主 loop 遠距回收**：hook 埋一個明說的懸念（「這個 X 我最後會給你完整答案」），**回收放在最後 1/3**。
   **開了必關**——沒回收 = 詐欺感，比沒開更傷（觀眾會記得你騙他，下一支不點了）。
4. **Micro-loop 本 beat 回收**（≤2 分鐘內關掉），只有主 loop 可以跨段。
   鐵則：**任何時刻至少有一個 loop 沒關**——關掉一個之前，先開下一個。
5. **Payoff 密度 60-90 秒**：每 60-90 秒要給一個**可以帶走的具體東西**（新結論／新數字／新示範結果）。
   不能連續兩分鐘都在鋪陳。鋪陳是給 payoff 用的，不是內容本身。
6. **資訊密度要呼吸**：600 字窗內塞 ≥6 個新概念、中間沒有任何例子或故事緩衝 = 過載。
   密集段與呼吸段**交替**，不是整支都密（整支都密 = 整支都沒重點）。
7. **時間錨定 micro-promise**：「接下來 30 秒你會看到它實際跑起來」——把長片切成一連串心理上的短衝刺。
   **講了要兌現**，而且要準時（說 30 秒就別拖到 2 分鐘）。
8. **一口氣測試**：單句 ≤35-40 字，**唸出來**換不了氣就拆。這條是全篇最便宜的節奏修法，而且只能用嘴驗，眼睛看不出來。
9. **價值排序**：**第二強的點開場、最強的壓軸**，中間由弱到強爬升。
   最強的點放開場會讓後面全程走下坡；壓軸給最強才有「看完」的理由。
10. **結尾三步**：① 扣回本片承諾 → ② 開一個新的 curiosity gap 導向下一支 → ③ **只推一個動作**（兩個 CTA = 零個 CTA）。
11. **初稿寫完整體砍 20-25%**：砍填充、砍重複舉例、砍自我說明，**招牌不動**（哪些是招牌 → `script-style-framework.md` 的贅詞／招牌準則）。
    這一刀通常是整份稿子留存提升最大的單一動作。

### 一個常見誤解

「節奏好」不等於「講很快」。節奏 = **資訊密度的變化**。
整支都快 = 沒有對比 = 觀眾疲勞後跳出；整支都慢 = 沒有推進 = 觀眾提早離場。
gate 的 `no_punch` / `beat_too_long` / `andthen_chain` 三條抓的都是**變化不足**，不是速度不足。

## §3 交付流程（三支柱怎麼串）

```
載入你的 voice profile（支柱 1）
   ↓
起稿（套 §2 的人工 craft ＋ §1 的六個消化句式）
   ↓
整體砍 20-25%（lean）
   ↓
load_vocab("你的 audience_vocab.json")
gate(text)  →  PASS 才錄音
   ├─ 語言 fail：擋死，一定要改
   └─ 節奏 warn：逐條看，能修就修（有意識地不修也行，但要是決定，不是忘記）
```

腳本檔格式建議：旁白正文 ＋ `>` 開頭的註記行。
gate 會自動忽略 blockquote——**註記不算旁白**：不計時長、不掃行話。
（所以你可以在稿子裡放給自己看的備忘、來源連結、對帳筆記，不會污染檢查結果。）
