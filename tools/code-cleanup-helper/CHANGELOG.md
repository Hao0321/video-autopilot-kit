# Changelog — code-cleanup-helper

## 2026-08-24 — long-source editorial-unit cardinality

- Added one-source → N complete promise/payoff deliverable auditing with distinct editable projects, decoded renders and receipts. Old candidate outputs cannot self-label ground truth; compilation fallback and unchanged recut fingerprints are calibrated false greens.

## v0.20.0 — 2026-08-24 (fresh public mirror contract)

- Documented the modular provider／orchestrator boundary for Skill, web, database, game, software and mixed-project R&D routes.
- Public sync now blocks privacy-token／pattern matches before writing any destination file.
- A managed-file manifest makes removed canonical files visible as `stale` and prunes only paths previously owned by the sync tool; public-only packaging remains untouched.
- Added negative fixtures for private markers and path traversal plus a manifest round-trip test.
- Release maintenance now requires strict private/public gates, explicit R&D external-change authorization and remote hash verification.

## 2026-08-23 — config-scope and extracted-security ownership audit

- Repository audits now distinguish target-local config from provider config and classify generated-dependency inventory explosions as measurement pollution.
- Desktop harness audit catches pre-body DOM reads and toolbar-only readiness that races lazy onboarding or editor routes.
- Security audit follows extracted responsibility modules and requires a negative fixture proving omission of the new module is detected.

## 2026-08-23 — desktop journey isolation and UI-density audit

- Harnesses that reuse operator WebView profiles, attach to stale processes, rely on translated copy selectors or replace readiness with fixed sleeps are now reviewable or failing according to evidence impact.
- UI-density audits retain the full visible-control inventory while gating enabled decisions and disabled signpost clutter independently.

## 2026-08-23 — native drop-path and trim semantics audit

- Desktop drag import must use the same durable path／probe／cache／canvas／Timeline pipeline as the native picker; browser object URLs and visual overlays do not close save／reopen integration.
- Timeline trim audit now catches opposite-edge drift, zero-frame ranges, silent outward extension and two-step Undo history.
- Rejected drag formats require visible user feedback.

## 2026-08-23 — preview discoverability and dev-first audit

- Preview cards hidden behind an unnamed generic advanced disclosure now count only as component presence; beginner readiness requires a visible category-naming entry and a fresh-profile findability journey.
- First-run guidance must be dismissible and permanently reopenable, while the default automatic-edit entry explains prerequisites and the next action.
- When the user explicitly requires development testing before packaging, installer evidence remains open and no stale package may be presented as the candidate.

## 2026-08-23 — Timeline boundary, ripple and first-source audit

- Direct-manipulation audit now treats track labels, toolbars, locked／incompatible lanes and outside-lane space as negative drop regions; invalid release must preserve both track and time.
- Ripple delete must close the exact declared synchronized gap in one atomic history entry and restore the full graph with one Undo.
- Portrait／landscape／square auto-canvas claims now require the delivered import path and decoded metadata; a starter placeholder cannot masquerade as prior user media and suppress first-source inference.

## 2026-08-23 — repeatable delivered-state and controller ownership audit

- Delivered journeys now isolate recovery, batch, update, remote-device and cache state from real user directories and must pass twice without a prior Autosave or modal changing the result.
- CDP／WebDriver requests are audited against their owning connection so a timed-out socket cannot poison a replacement connection's pending commands.
- A controller timeout is classified separately from a product freeze until an independent UI or backend probe reproduces the failure.

## 2026-08-23 — direct-manipulation and harness-failure audit

- Timeline audit now follows the complete press／multi-move／release stream, catches hit-testing or pointer-capture loss after the first frame, and requires one canonical history commit plus durable Undo／Redo／Autosave evidence.
- A fast drag calculator, interval index or native scheduler cannot close a missing UI-event path; transient compositor movement and release-time domain commit are audited separately.
- Nested delivered runners must preserve the primary failure, await their owned process tree before cleanup, and use real wall-clock deadlines rather than multiplying attempts by hidden probe timeouts.
- Raw／gzip／CSS bundle budgets remain independent exact ceilings; even a one-byte overage must be removed in code instead of hidden by raising the threshold.

## 2026-08-23 — cold extracted-runtime and controller audit

- Delivered desktop cold starts must be observed while the packaged runtime is still pending; a later successful backend receipt does not prove that the editor stayed usable.
- A monolithic CDP／WebDriver expression that awaits unrelated media, model, library and update calls is now a controller-design finding because one timeout destroys stage attribution and may poison the connection.
- Audit journeys should use short UI heartbeats plus separately bounded backend stages, preserve controller-timeout counts, and assert durable state／output invariants instead of transient shared status text that background jobs may legitimately overwrite.

## 2026-08-22 — non-blocking desktop background-job audit

- Long update/download/model/media operations invoked through desktop IPC must return a queued state immediately and complete through bounded polling or events.
- Added duplicate-job coalescing, terminal-result persistence, timeout/error settlement and input-responsiveness checks while the backend is slow or unavailable.
- A backend receipt that eventually succeeds no longer proves UI fluidity when the WebView/main thread was blocked during the request.
- Repeated third-party license bodies may be narrowly excluded from structural duplication metrics only when a separate closed-world rights/SBOM gate inventories the delivered license bytes; broad `*.txt` or notices exclusions remain invalid.
- Synthetic browser lifecycle events such as `beforeunload` may destroy or navigate a desktop WebView during CDP smoke tests; audit guard policy with deterministic units and use a real navigation/dialog protocol for delivered acceptance.

## 2026-08-22 — permanent QR device-binding audit

- Distinguished scan-once device authorization from a long in-memory session.
- Added short-lived QR exchange, per-device credential rotation, host-side hash-only storage, restart reconnect, stop-versus-revoke semantics and exact-device revocation checks.
- Long-lived credentials in URLs, logs, receipts, installers or plaintext host stores are now explicit Remote security findings.

## 2026-08-22 — professional media workstation false-green gates

- Split professional Timeline fluidity from planner/query speed and require delivered UI viewport, materialization, input-to-state, Undo and interaction evidence.
- Added bundled-font provenance → SBOM/notices → extracted closed-world payload → renderer-selection closure, including non-recursive font-directory and system-fallback negatives.
- Split source-frame scopes from decoded color output and calibrated-display parity; unknown Log and duplicate-look application remain explicit failures.
- Director-console machine-ready states can no longer be promoted to human approval or certification without authenticated human evidence.

## v0.19.0 — 2026-08-22 (batch fan-out and editable re-entry)

- Distinguishes true batch auto-editing from multi-import, repeated calls and concatenation onto one timeline.
- Requires closed-world source/group → durable job → editable project → render → receipt evidence, with source hash preservation and current provenance.
- Adds failure isolation, per-job retry, interrupted-job recovery, unsafe/shared-output rejection, immutable published artifacts and delivered open-in-editor checks.
- Keeps unit fan-out or file presence at `NOT_CHECKED` until a delivered desktop journey proves editable re-entry.

## v0.18.0 — 2026-08-22 (model／reasoning and Markdown／JSON contracts)

- 新增 model／reasoning／Markdown／JSON contract audit：模型名稱不再被當成品質或信任證據。
- 要求每次 invocation 保存 provider、model、effort、context hash、evaluation state 與 fresh receipt；每個 model × effort cell 必須以同 provenance benchmark 獨立量測。
- Markdown 明確降為 bounded semantic router，JSON schema／negative gate／executor receipt 才是可執行真相；缺 benchmark 時回報 `NOT_CHECKED model-quality-evaluation`。

## v0.17.1 — 2026-08-22 (runtime-floor harness replay)

- Runtime-gated built-ins now require a child-level receipt from the exact supported interpreter.
- An unsupported-runtime harness failure remains measurement evidence until the identical harness passes under the declared floor; it cannot be relabelled as product failure or PASS.

## v0.17.0 — 2026-08-22 (semantic handoff and legacy-schema closure)

- Cross-system audits now require a closed-world semantic handoff surface; a generic command array cannot stand in for brief, narrative, transition/audio evidence, quality, artifact and outcome obligations.
- Legacy compatibility is explicitly separated from current-workflow closure, with current schema identity required in flow receipts.
- Capability matrices distinguish native evidence, calibrated contract enforcement, orchestrator handoff, unmeasured experiments and external blockers.
- Free community distribution remains a redistribution scope; zero price is not provenance for music, SFX, fonts, stock, models or generated/source assets.

## v0.16.0 — 2026-08-22 (cross-system and claim-state closure)

- Component presence no longer counts as cross-system integration: mutable Skill/Agent, MCP/API, runtime, installer, human review, publish and outcome edges require a same-revision journey and versioned handoff receipt.
- A product that consumes the newest private Skill should carry invocation revision/hash and bounded rule IDs instead of freezing private Skill text or full memory into the installer.
- Instrument GREEN with an honest `unmeasured` claim remains product/parity BLOCK; market leadership needs a closed baseline×surface matrix with independent evidence.

## v0.15.2 — 2026-08-22 (evidence CLI argument boundary)

- Evidence runners must exclude option values such as `--output report.json` from positional target discovery and assert the report's resolved target identity after writing.
- Requires calibrated option-only and explicit-target argument-order fixtures so a successful file write cannot conceal an audit of the wrong root.
- Wrapper／transpiler flag consumption is a separate boundary: use a calibrated separator or direct pinned-runtime loader and retain the child argv instead of assuming an application-parser fix preserves arguments.

## v0.15.1 — 2026-08-22 (mixed-language and hotspot closure)

- Mixed TypeScript／Rust repositories must keep Cleanup's cross-language architecture result visibly `NOT_CHECKED` and pair it with a separate product-native graph／cycle／boundary gate; lowering `--require-checked` cannot become a whole-repository architecture claim.
- Long-file and responsibility findings are closed by extracting a named responsibility and replaying typecheck, tests, native architecture and delivered UI evidence; raising the global threshold solely to erase a finding is prohibited.

## v0.15.0 — 2026-08-22 (security and anti-unpack closure)

- Added a dedicated release-security route that treats impossible-to-guarantee unpack resistance as a cost increase, not a security claim.
- Repository audits now surface production executable／unsigned-update environment overrides, Electron IPC／media boundaries, MCP symlink escape, Remote Origin／CSP／rate-limit gaps and internal／public restricted-pack drift.
- Actual installer extraction, secret／source-map scanning, closed-world native payload, signing and PE exploit mitigations remain project-native gates; absent runtime evidence is `NOT_CHECKED`, never inferred from source or build-directory binaries.
- Requires calibrated attack fixtures and latest-revision replay after security evaluator changes.
- Requires authorized Remote journeys to be replayed alongside Origin／CSRF negatives and preserves bounded child stdout when stderr is empty, preventing secure-policy regressions and opaque exit-code-only failures.
- Build-runtime provenance now requires a manifest-bound version／source／executable-hash receipt; PATH prepending or the later evidence collector's runtime version cannot prove which interpreter performed compile／bundle work.

## v0.14.0 — 2026-08-22 (lazy payload and restricted-pack closure)

- Build-receipt guidance now requires every emitted lazy JavaScript／CSS chunk to remain in output identity; a smaller main bundle cannot hide growth in untracked secondary chunks.
- Delivered UI journeys must trigger claim-critical lazy surfaces at least once, so missing Motion Studio／QR／optional-editor chunks cannot pass an initial-shell smoke.
- Resource packs separate compact manifest freshness from authoritative closed-world installer payload comparison; exact extracted bytes remain mandatory even when the build receipt does not duplicate every large asset entry.
- Restricted owner-only packs must preserve fail-closed redistribution metadata in the actual installer, and internal delivery evidence cannot promote a public-redistribution obligation.

## v0.13.0 — 2026-08-22 (private source-asset boundary)

- Artifact-set guidance now pairs public generated outputs with private source references without excluding source bytes from freshness inventory.
- Requires `forbid_globs` for source-role leakage into public／static／upload roots; one-to-one pairing no longer implies both sides should be web-accessible.
- Separates Cleanup's file-location proof from R&D HTTP evidence for public API omission, legacy 404 and authenticated operator access.

## v0.12.0 — 2026-08-22 (launcher-integrity evidence)

- Provider／test／build 結果不再只信父層 shell exit；要求 child executable 啟動身分、child exit 與成功 marker。
- 明列 PowerShell command-not-found 可能保留舊 `$LASTEXITCODE` 的假綠燈模式，並把 launch／timeout／marker 缺失分類為 measurement failure。
- Alias-sensitive proxy／symlink 必須保留 invocation path，同時另存 physical target identity，避免 canonicalize 後破壞 `argv[0]` 行為。
- Windows shell wrappers 不算 shell-free child 證據；必須顯式鎖定符合 version floor 的 interpreter/runtime。
