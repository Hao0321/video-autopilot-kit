# Cross-system journey core

Use this card when multiple components are claimed to form one working product flow.

- `cleanup.integration.same-revision`: bind source, generated assets, runtime, installer, adapters, and receipts to one current revision/hash set.
- `cleanup.integration.versioned-handoff`: every ownership boundary has a versioned schema, producer receipt, consumer validation, and stale/forged negative fixture.
- `cleanup.integration.journey-not-presence`: component, command, button, tool-list, or exit-0 presence is not an end-to-end PASS. Require a real input, durable mutation, output, and claimed review/publish/outcome state.
- `cleanup.integration.closed-world`: the declared capability/flow/tool inventory has a consumer-owned required set and a missing-one-must-fail fixture; self-comparing two arrays from the same JSON is vacuous.
- `cleanup.integration.fresh-final`: after the last relevant change, rerun the delivered journey and freshness/revision gates. Open or unmeasured edges remain `NOT_CHECKED`.

For legacy or unusually broad audits, use `../cross-system-integration-audit.md` as an explicit fallback and record the extra context cost.
