# Community contribution audit

Select for requested PR adoption, retrospective merged-change audits, or collaborator verification. Keep raw histories, identities, paths and probes in the target's `.rd/`.

- `cleanup.community.inventory`: paginate the requested authors/states; separate open, merged and closed-unmerged. Review the actual merged delta and current-main ancestry for merged work. Freeze heads, full file lists and diff hashes, then read back freshness before delivery.
- `cleanup.community.version`: bind each result to its tested head, edition, dependencies and environment. A locally repaired candidate cannot certify its contributor's original head. Preserve test exclusions and missing runtimes; a source build does not certify an installer.
- `cleanup.community.attribution`: classify product, evaluator, configuration and unavailable-source failures. Use the unchanged baseline to attribute a defect; retain an unrelated required CI failure as a gate failure. Review final merged bytes when an earlier finding was fixed before merge.
- `cleanup.community.security-chain`: for touched boundaries, test input through recovery/grants, staged bytes through launch/load, and accepted input size through parsing work. Use harmless owned fixtures and intercept execution where sufficient. Historical download hashes and readonly paths alone cannot certify runtime identity.
- `cleanup.community.dependency-closure`: trace built/staged/loaded artifacts to manifests and independent lockfiles. Folder names such as experiments/spikes are not evidence of exclusion. Distinguish maintenance notices, vulnerability reachability and malicious-code evidence; report registry-query omissions.
- `cleanup.community.required-ci`: compare proposed check names and permissions with live branch protection. Preserve equivalent aggregate gates and fail on unmet needs. Measure speed claims; completing a merge-tree is not adoption evidence.
- `cleanup.community.access`: read collaborator membership, pending invitations, effective role and visibility. Public read access is not a collaborator invitation or direct-write grant. State current access without inferring the entire invitation history; access changes require user authorization.
- `cleanup.community.adoption`: record product fit, complete workflow, measured benefit, security and maintenance cost separately. Safety/maintenance improvements can have value without adding features. Passing tests cannot override an explicit user constraint; avoid rejecting useful work solely by author or PR count.

For formal security claims also select the existing security contract; this card issues no certification. Adoption experiments use the reciprocal [R&D card](../../../run-benchmark-driven-rd/references/topics/community-pr-adoption.md).
